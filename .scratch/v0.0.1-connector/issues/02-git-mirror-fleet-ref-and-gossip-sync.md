# 02: Git-native `Mirror repo`, `Fleet ref` staging, `Land`, and `Gossip sync`

**What to build:** Peer `Node`s can exchange code state using compact `git bundle` files (never SMB/NFS), automatically provision on-demand `Mirror repo` directories (`<paseoHome>/connector/repos/<canonical-slug>`) when receiving work for an uncloned `Project`, silently stage completed peer commits into `refs/fleet/<nodeId>/<runOrTaskId>` (`Fleet ref`) without touching the user's active working tree, land a `Fleet ref` on demand, and reconcile `free-pool.json` + completed `BurnRunRecord` reports via last-write-wins `Gossip sync`.

**Blocked by:** 01: Fleet registry, `Node posture`, `Health guard`, and low-bandwidth `Fleet pulse`

**Status:** ready-for-agent

- [x] `createCommitBundle` and `ensureMirrorRepoFromBundle` package `<base>..HEAD` (plus `.worktreeinclude` files) from an initiating repository and unpack/update `<paseoHome>/connector/repos/<canonical-slug>` on a target `Node`.
- [x] `stageFleetRefFromBundle` unpacks a peer `Node`'s completed commit bundle into `refs/fleet/<nodeId>/<runOrTaskId>` in the local Git repository while leaving the active working tree and index untouched.
- [x] `landFleetRef` checks out or merges `refs/fleet/<nodeId>/<runOrTaskId>` into a local branch (`fleet/<nodeId>/<runOrTaskId>`) when explicitly invoked by the operator.
- [x] `reconcileGossipSync` compares `freePoolUpdatedAt` and run timestamps from `Fleet pulse` digests and reconciles newer `free-pool.json` and completed `BurnRunRecord` / `report.md` artifacts across `Node`s.
- [x] Behavioral unit tests in `test/git-sync.test.ts` pass against real temporary Git repositories on disk.

## Comments

Implemented on integration/v0.0.1-connector at 61e9c23 — `src/git-sync.ts` (634 lines, mirrored verbatim to `plugin/server/core/git-sync.ts` via `sync:plugin-core`, exported through `src/index.ts`) implements `createCommitBundle` (packages an initiating repo's `<base>`..HEAD range with base ancestry-validated, plus a tar of `.worktreeinclude`-matched untracked files with the same pattern semantics as paseo-factory), `ensureMirrorRepoFromBundle` (provisions/updates `<paseoHome>/connector/repos/<canonical-slug>` Mirror repos from those bundles — fresh clone with origin dropped, existing mirrors fast-forwarded, include files re-extracted, slug/ref-component traversal guards), `stageFleetRefFromBundle` (fetches a peer completion bundle into `refs/fleet/<nodeId>/<runOrTaskId>` with force-overwrite on re-stage, leaving working tree, index, HEAD, and branch byte-for-byte untouched — asserted against a dirty tree with staged changes), `landFleetRef` (applies a staged ref via `checkout -B fleet/<nodeId>/<runId>` or merge into the current branch; ff and diverged merge both covered), and `reconcileGossipSync` (last-write-wins pulls of burn-lab/free-pool.json and completed BurnRunRecord JSON + `runs/<runId>/report.md` gated on Fleet pulse `freePoolUpdatedAt`/`runsUpdatedAt` stamps, paths matched to factory-burn-lab's own layout at `src/free-pool.ts:110` and `src/burn-engine.ts:560-566`, with `createSshGossipTransport` as the BatchMode/ConnectTimeout=5 SSH default and an injectable `GossipArtifactTransport` seam for offline tests); 22 behavioral tests in `test/git-sync.test.ts` drive real temporary git repositories on disk through the public functions, developed red→green across 5 conventional commits. Deviations: `createCommitBundle` emits a self-contained bundle (`git bundle create out HEAD <branch>` — full history to HEAD) instead of a thin `<base>`..HEAD-only bundle — a thin bundle records `<base>` as a prerequisite and git refuses to clone/fetch it anywhere lacking those commits ("Repository lacks these prerequisite commits", verified experimentally), which would break provisioning fresh Mirror repos on peers that never cloned the project; base is still validated (`merge-base --is-ancestor`) and recorded in the result, and existing mirrors dedupe objects on fetch and still advance only to the bundle HEAD; `ensureMirrorRepoFromBundle` updates an existing mirror via `git fetch <bundle> HEAD` + `git merge --ff-only FETCH_HEAD` instead of fetching into the branch ref — git refuses to fetch into a checked-out branch (verified experimentally) — and fresh provisioning drops the stale `origin` remote that would point at the transient bundle path; `landFleetRef` merge mode merges the Fleet ref into the CURRENT branch (fast-forwarding when behind, merge commit when diverged) while checkout mode (default) materializes and switches to the local `fleet/<nodeId>/<runOrTaskId>` branch — reading the ticket's "checks out or merges" against the spec's "checkout or fast-forward/merge a Fleet ref"; in merge mode `LandedFleetRef.commit` reports the resulting HEAD; `GitBundleTransport` (cross-Node bundle shipping over SSH) is NOT introduced in this ticket — the ticket's checkboxes require only local git seams (CommandRunner-injected, reusing fleet.ts's), the spec names GitBundleTransport collectively across fleet/git-sync/dispatch, and the actual bundle transfer belongs to dispatch (ticket 03), which reuses these functions unchanged; `createSshGossipTransport.readFile` maps both non-zero cat exits and empty SSH reads to null (and listFiles failures to []) so a peer's absent artifact never fails a gossip pass; no upstream hook in `../research-slp` was needed (its `.worktreeinclude` semantics were reimplemented in ~30 lines per pattern-matching docs at `plugin/bin/task-worktree.mjs:108-152`), so no burn-lab-upstream issue was filed and nothing under `../research-slp` was modified.
